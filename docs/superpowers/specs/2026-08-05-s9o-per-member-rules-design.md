# Спека: пер-участница проверки `rotation`/`forkAccess` в групповом магните (`LKWkalk-s9o`)

Дата: 2026-08-05 · Задача: `LKWkalk-s9o` (P3) · Предшественники: `LKWkalk-v1m` (PR #56),
`LKWkalk-p3p.17` (PR #80)

## Предмет

`resolveGroupDrop` (`packages/engine/src/packing/resolveDrop.ts:290-324`) обходит участниц группы
циклом `for (const ref of unique)` и на каждой проверяет два позиционно-независимых правила типа
груза: `rotation` (стоит ли колонна в разрешённой ориентации) и `forkAccess` (не пришпилил ли режим
погрузки другую ориентацию). Нарушение — досрочный отказ.

**Проверка корректна. Некорректно доказательство.** Оба существующих теста этой дыры (`v1m`,
`resolveDrop.test.ts:267` и `:290`) используют группу из ОДНОЙ стопки. На однорефной группе «обойти
всех» и «проверить `unique[0]`» — буквально одно и то же выражение, поэтому мутация «судить только
первую участницу» такие тесты переживает.

Это тот же класс слепоты, что исправлен в `p3p.17` для стенок отсеков, и заведён он был там же.

**Продкод не меняется.** Ожидается, что он уже верен. Изменяется один файл —
`packages/engine/src/packing/resolveDrop.test.ts`.

## Ключевая трудность и её решение

`rotation` и `forkAccess` — свойства **типа груза**, а нарушение зависит от **ориентации колонны**.
Значит «нарушителем сделана не первая участница» достижимо двумя способами, и они ловят разные
мутации:

| Устройство группы | Ловит «судить только `unique[0]`» | Ловит «проверить каждый `cargoTypeId` один раз» |
|---|---|---|
| два разных типа груза | да | **нет** (типы разные — дедуп законен) |
| один тип, две ориентации | да | **да** |

Выбран **один тип в двух ориентациях**: правдоподобная оптимизация «вынести проверку правила из
цикла по колоннам, судить по типу» опаснее грубой диверсии (грабли `p3p.17` №2), а поймать её умеет
только эта фикстура.

Смесь ориентаций у одного типа достижима вживую: `rotateStack` (`edit.ts:233`) флипает одну колонну
на месте, после чего правило типа меняют.

## Фикстура

`mixedOrientationPair(order)` — внутри существующего `describe('resolveGroupDrop')`
(`resolveDrop.test.ts:155`), сразу после тестов `v1m`.

| | |
|---|---|
| Кузов | существующий `V` файла — 10000 × 2400 × 2650 |
| Груз | ОДИН тип: поддон 1200 × 800, `quantity: 2`, `rotation: 'yawOnly'` |
| Раскладка | `layoutOf([A, B], 0)` — файловый хелпер `resolveDrop.test.ts:33` |
| Колонна A | `(0, 0)`, ориентация `'lwh'` → footprint 1200 × 800 |
| Колонна B | `(4000, 0)`, ориентация `'wlh'` → footprint 800 × 1200 |
| `refs` | параметризованы: `[A, B]` и `[B, A]` |

Раскладка задаётся руками, а не через `calculateLayout`: полный контроль координат и порядка, и
фикстура переживёт замену полочного упаковщика на max-rects (`LKWkalk-i1p` в бэклоге).

Берётся готовый файловый хелпер `layoutOf(placements, unplaced)` вместо идиомы `p3p`
`{ ...packLoad(load), placements, unplaced }`: он собирает раскладку целиком, поэтому `metrics`
согласованы с рукотворными `placements`, а не остаются от чужого прогона упаковщика.

## Тесты

Все негативные сценарии целятся `{ dx: 0, dy: 0 }`: «остаться на месте» геометрически законно,
поэтому отказ может прийти только от пер-участница проверки, а не от поиска дельты.

| Тест | Что меняем в `load` ПОСЛЕ расчёта | Инстансы | Ожидание |
|---|---|---|---|
| rotation | `rotation: 'none'` → разрешён только `'lwh'` | `[A,B]`, `[B,A]` | `ok:false`, `ERR_EDIT_ROTATION`, payload `orientation === 'wlh'` |
| forkAccess | `forkAccess:'twoSides'`, `forkAxis:'length'`, `loadingMode:'rear'` → пришпилен `'lwh'` | `[A,B]`, `[B,A]` | `ok:false`, `ERR_EDIT_FORK_ACCESS`, payload `orientation === 'wlh'` |
| контроль ложного отказа | ничего (правила исходные) | один | `ok:true`, `dx:0`, `dy:0` |

Итого пять экземпляров теста. Точное итоговое число тестов набора берётся из фактического прогона, а
не из арифметики плана (грабли `p3p.17` №5).

Обоснования деталей:

- **В тесте forkAccess `rotation` остаётся `'yawOnly'`.** В цикле `rotation` проверяется РАНЬШЕ
  `forkAccess`; при `rotation:'none'` колонна B упала бы на вращении, и тест доказывал бы не то
  правило.
- **Доказательство «судили вторую» несёт `orientation`, а не `cargoTypeId`.** Тип один — `'p'` у
  обеих участниц, и в payload он ничего не различает. Ориентация `'wlh'` есть только у B.
  `cargoTypeId` ассертится как проверка контракта ошибки, но не как доказательство обхода.
- **Контрольный тест обязателен.** Без него первые два неотличимы от «фикстура нелегальна сама по
  себе»: проверка должна отвергать нелегальное, не запрещая легального.
- **Порядок `refs` параметризован.** Если бы нарушителем всегда была последняя участница, мутация
  «судить только `unique.at(-1)`» (или обратный обход с досрочным выходом) тесты пережила бы. Два
  порядка доказывают «судят КАЖДУЮ», а не «судят не первую».

## Приёмка — мутационная

Зелёный прогон сам по себе не доказывает ничего: набор был зелёным и ДО работы. Критерий приёмки —
три мутации продкода, каждая обязана покраснеть, и откат обязан позеленеть.

| Мутация | Что делаем с `resolveDrop.ts:290-324` | Обязана покраснеть |
|---|---|---|
| M1 | судить только `unique[0]`, остальных пропускать | инстанс `[A, B]` тестов 1–2 |
| M2 | проверять каждый `cargoTypeId` один раз (вынести правило из цикла по колоннам) | инстанс `[A, B]` тестов 1–2 |
| M3 | судить только `unique.at(-1)` | инстанс `[B, A]` тестов 1–2 |

На фикстуре из одного типа M2 поведенчески вырождается в M1: обе судят только первую встреченную
колонну. Это не делает M2 лишней — наоборот, это и есть довод за такую фикстуру. На группе из ДВУХ
разных типов дедуп по `cargoTypeId` законен, и M2 прошла бы незамеченной, тогда как M1 умерла бы.

Смотреть надо не только «покраснело», но и КАКОЙ тест на какой фикстуре: перехват мутации в чужом
файле (например, в `edit.test.ts` на фикстуре без смешанных ориентаций) не является доказательством
про предмет этой работы (грабли `p3p.17` №3).

## Осознанно вне объёма

- **Мутация «взять правило по `unique[0].cargoTypeId` для всех участниц»** на группе из одного типа
  неотличима от корректного кода. Ловится только фикстурой с ДВУМЯ типами груза. Решение владельца —
  не расширять объём `s9o`; пробел зафиксирован в задаче `LKWkalk-5iw`.
- **Мутация «поменять местами проверки `rotation` и `forkAccess`»** требует участницы, нарушающей
  оба правила сразу. Порядок кодов ошибок нигде не специфицирован — ценность низкая.
- **Запись в `CHANGELOG`** не делается: работа не меняет ни контракта, ни поведения, ни
  пользовательского эффекта. Так же поступили в `p3p.17`.
