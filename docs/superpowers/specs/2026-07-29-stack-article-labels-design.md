# Подписи артикулов на стопках (`LKWkalk-ayg`)

Дата: 2026-07-29. Статус: утверждено пользователем, к реализации.

## Задача

На схеме раскладки стопка подписана только количеством (`×28`). Что за груз лежит — по картинке
не понять: имя артикула живёт в `<title>`/`aria-label` и в легенде внизу листа. Человек, который
смотрит на распечатанный ладеплан у машины, вынужден сверять цвет с легендой.

Добавить к количеству название артикула там, где стопка нарисована прямоугольником.

## Границы

- Затрагивается только презентация (`apps/web`). Движок, контракт и локали данных не меняются.
- Вид сверху (`CrossSection`, `TopView`) и склад (`WarehouseFloor`). **Боковой разрез не трогаем** —
  там сегодня нет подписей вообще, и это осознанно.
- Ни одной жёсткой строки: всё, что не имя артикула (оно приходит из данных), — ключи локалей.

## Решение

### Что рисуем

Внутри прямоугольника стопки — блок из двух строк, центрированный по стопке так же, как сегодня
центрируется одиночное `×N`:

```
┌────────────┐
│            │
│   EPAL 1   │  имя: countFont × 0.7, вес 600, --muted
│    ×28     │  количество: countFont, вес 700, --ink (как сейчас)
│            │
└────────────┘
```

Количество сохраняет нынешний размер и вес — оно остаётся главным числом схемы. Имя тише по
размеру и цвету, чтобы не спорить с ним.

`countFont` не меняется: он уже единый по схеме (`vehicle.width * 0.05` в мм-единицах вида
сверху) и намеренно не зависит от площади стопки.

### Обрезка

Шрифт имени единый по всей схеме — стопки не «прыгают» размерами (решение пользователя).
Не влезло по ширине — режем и ставим `…`: `EPAL 2 (2-s…`.

Ширина текста **оценивается арифметически**: `len × 0.58 × fontSize`. Не `getComputedTextLength`:
измерение по DOM недоступно в jsdom, и юнит-тесты разошлись бы с продом — правило проверено на
граблях сессии 5nb (jsdom не видит раскладку). Коэффициент 0.58 — средняя ширина глифа для
`--font-sans` в этом шрифтовом стеке; ошибка в пределах одного символа приемлема, потому что
результат — только решение «сколько символов оставить», а не позиционирование.

Полное имя остаётся доступным: `<title>` и `aria-label` уже несут `${cargo.name} ×${units}` и не
меняются.

### Когда имя не рисуется

Остаётся только `×N` — ровно то, что на схеме сегодня:

1. стопка ниже, чем нужно двум строкам (`boxH < countFont * 1.9`);
2. после обрезки осталось меньше 3 символов — огрызок вида `E…` не несёт смысла;
3. групповая стопка смешанного типа: у неё нет одного артикула, там уже стоит `ladeplan.groupGhost`.

### Где живёт логика

Чистая функция в отдельном модуле рядом с `cutaway.ts`:

```ts
stackLabel(name: string | null, boxW: number, boxH: number, countFont: number): string | null
```

Возвращает готовую строку имени (уже обрезанную) либо `null` — «не рисовать». Компоненты только
рисуют то, что она вернула. Тестируется юнит-тестами без рендера: влезающее имя, обрезка,
все три случая деградации, границы порогов.

## Проверка

- Юнит-тесты `stackLabel` — обрезка и деградация.
- Настоящий Chrome (CDP) на демо-данных: подписи читаются на всех восьми цветах палитры заказов,
  не вылезают за прямоугольники, мелкие стопки корректно остаются без имени.
- `Page.printToPDF` — подписи читаемы в печати. Если сжатие листа под одну страницу (`LKWkalk-7hx`)
  сделает их нечитаемыми, порог из пункта «когда имя не рисуется» становится общим решением обеих
  задач.
