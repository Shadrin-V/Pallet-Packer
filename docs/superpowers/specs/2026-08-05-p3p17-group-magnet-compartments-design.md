# Доказательство отсеков в групповом магните (LKWkalk-p3p.17)

Дата: 2026-08-05 · Статус: утверждён владельцем · Контракт движка `0.18.0` — **не меняется**

## Задача

`resolveGroupDrop` (магнит групповой правки, ADR 020 + ADR 021) обязан уважать стенки отсеков для
**каждой** участницы группы. Проверка стоит в `inBounds` (`packages/engine/src/packing/resolveDrop.ts`):

```ts
const inBounds = (ddx, ddy) =>
  members.every(
    (m) =>
      fitsInSomeCompartment(load.vehicle, m.x + ddx, m.dx) &&
      m.y + ddy >= 0 &&
      m.y + ddy + m.dy <= load.vehicle.width,
  );
```

Код верен. Неверно **доказательство**: оба существующих p3p-теста группового пути идут через хелпер
`singleAtWall()` — группа из ОДНОЙ стопки. На группе из одного участника `members.every(…)` и
«проверить `members[0]`» — одно и то же выражение, поэтому тесты не отличают корректную проверку от
двух правдоподобных поломок.

Это не гипотеза. Обе поломки внесены в производственный код и прогнаны:

| Мутация | Что ломает | Реакция набора **до** этой работы |
|---|---|---|
| **M1**: `members.every(` → `[members[0]].every(` | отсеки и границы для всех участниц, кроме первой | `resolveDrop.test.ts` — **27/27 зелёные**. Краснеет только `edit.test.ts` на фикстуре `pallets, realistic LKW hold`, у которой **отсеков нет** — то есть про отсеки этот перехват не говорит ничего |
| **M2**: отсек ищется один раз по `members[0]`, остальные судятся его границами (правдоподобная «оптимизация»: вынести поиск отсека из цикла) | группу, легально стоящую сразу в ДВУХ отсеках | **277/277 зелёные** — невидима полностью |

M2 — не выдуманная диверсия, а естественное «упрощение» для того, кто не держит в голове, что группа
может пересекать сцепку. Сегодня в репозитории нет ни одного теста, который бы его остановил.

## Решение владельца

Объём — **только отсеки**, по букве задачи. Та же слепота «проверена лишь первая участница» есть у
пер-участница проверок `rotation`/`forkAccess` (`LKWkalk-v1m`, `resolveDrop.ts:300-321`: их тесты тоже
однорефные) — в эту работу не входит.

Помимо трёх точечных тестов ставится сеть: существующий sweep-инвариант прогоняется ещё и по паре.

## Дизайн

Производственного кода работа не меняет. Меняется один файл —
`packages/engine/src/packing/resolveDrop.test.ts`, блок
`describe('resolveGroupDrop — стенки каждого отсека (p3p)')`.

### Фикстура

Кузов из существующего блока, без изменений: длина 5800, ширина 2400; отсеки `a` = [0, 2400),
`b` = [3400, 5800); физический разрыв 1000 мм. Груз — кубик 1200×1200×1200, `rotation: 'none'`,
поэтому dx = dy = 1200, а допуск магнита по умолчанию = min(dx, dy) / 2 = **600**.

Рядом с существующим `singleAtWall()` появляется `pairAcrossBays(xA, xB)`: та же пара `load`/`layout`,
но `placements` — две стопки на y = 0 с заданными x, и `refs` в порядке `[A, B]`.

Порядок `[A, B]` — load-bearing: `members` строится обходом `refs`, поэтому нарушителем во всех
сценариях сделана **вторая** участница. Если бы нарушала первая, M1 отвергла бы дельту по той же
причине, что и корректный код, и тест бы её пропустил.

### Сценарии

Числа ниже не прикинуты — каждый прогнан на реальном движке до написания спеки.

| # | Расстановка | Прицел | Ожидание | Убивает |
|---|---|---|---|---|
| 1 | A@1200 (`a`, впритык к дальней стенке), B@3400 (`b`, впритык к ближней) | dx = −1000, dy = 0 | `ok: false`, `error.code === 'ERR_EDIT_OUT_OF_BOUNDS'` | M1 (даёт `ok`, dx = −1200 → B встаёт в разрыв на [2200, 3400)) |
| 2 | A@0 (`a`), B@3600 (`b`) | dx = +1200, dy = 0 | `ok: true`, **dx = 1000** | M1 (даёт 1200 → B торчит за кормой на [4800, 6000)), M2 (ложный отказ) |
| 3 | A@0 (`a`), B@3600 (`b`) | dx = 0, dy = 0 | `ok: true`, dx = 0 | M2 (ложный отказ: группа не может даже остаться на месте) |

Сценарий 1 — «магнит **отказал**», сценарий 2 — «магнит **скорректировал**»: тянет не туда, куда
пустила бы одна первая участница (1200), а туда, куда пускает замыкающая (1000). Сценарий 3 —
контрольный: проверка обязана отвергать нелегальное, не запрещая легального.

Разбор сценария 2, чтобы число 1000 не выглядело подгонкой. Кандидаты по оси длины — дельты, при
которых какая-то участница встаёт к стенке какого-то отсека, отфильтрованные допуском 600 от прицела
1200: от A (x = 0) годится 1200 (A → дальняя стенка `a`), от B (x = 3600) годится 1000 (B → дальняя
стенка `b`); плюс безусловно посеянный прицел 1200. Обе дельты одинаково «впритык», поэтому побеждает
ближняя к прицелу — 1200. Она проходит `inBounds` для A и проваливает для B, и магнит переходит к
следующей — 1000, где помещаются обе.

### Сеть под точечными тестами

Существующий инвариант блока — «если `resolveGroupDrop` сказала ok, `moveStacks` по этой дельте не
откажет» (ADR 020 для группы) — сегодня прогоняется только по `singleAtWall`. Он параметризуется по
обеим фикстурам, `singleAtWall` и `pairAcrossBays`, с тем же перебором dx/dy.

## Критерий приёмки

Зелёный прогон здесь **ничего не доказывает** — набор был зелёным и до работы. Работа принята, когда:

1. `npm test -- packages/engine/src/packing/resolveDrop.test.ts` зелёный на неизменённом движке;
2. этот же прогон **краснеет** под M1;
3. этот же прогон **краснеет** под M2;
4. после отката обеих мутаций `npm test`, `npm run typecheck`, `npm run lint` с корня зелёные, а
   `git diff` по `packages/engine/src/packing/resolveDrop.ts` пуст.

Пункты 2 и 3 проверяются физической правкой производственной строки, а не чтением теста.

## Что работа не трогает

Контракт движка не меняется — поведение то же, меняется только его доказательство. Без бампа версии,
без правок `docs/api-contract.md`, без нового ADR. Локали, UI и сервер не затрагиваются.
