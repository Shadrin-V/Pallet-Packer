# UI-пачка: двор, темы, ширина чертежа, перестановка, кнопка расчёта — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Упростить двор склада до пунктирной зоны, ввести вторую фирменную палитру с переключателем, вернуть чертежу полную ширину при выключенной кабине, разрешить перестановку стопок во дворе и вернуть кнопку расчёта вниз страницы.

**Architecture:** Правки живут только в `apps/web`. Движок и его контракт (`0.15.0`) не трогаются. Три из семи задач делят одну геометрию — ширину внешнего `viewBox`, которой владеет `truckFrame()`, — и одно множество токенов в `theme.css`. Порядок задач задан этими двумя общими ресурсами, а не списком владельца.

**Tech Stack:** TypeScript, React 18, Vite, Tailwind (токены через CSS-переменные), Vitest + @testing-library/react + jsdom.

**Спека:** [`docs/superpowers/specs/2026-08-03-ui-batch-design.md`](../specs/2026-08-03-ui-batch-design.md)

## Global Constraints

- **Ни одной пользовательской строки в коде** — только ключи локалей. Стартовые словари: `packages/i18n/src/dictionaries/de.ts` и `ru.ts`. Новый ключ добавляется в **оба**.
- **Ни одного hex вне `apps/web/src/theme.css`.** Единственное исключение — `apps/web/src/lib/orderColor.ts` (восемь цветов серий, нужны в JS для экспорта, одинаковы в обеих палитрах).
- **Внутренние единицы — целые миллиметры** ([ADR 002](../../adr/002-integer-millimeters.md)). Дробные значения допустимы только в презентационной рамке чертежа (`truckFrame.ts`), как там и оговорено.
- **TDD обязателен:** тест пишется раньше кода и проверяется на красном. Формулировка «Expected: FAIL with …» в шагах — это то, что действительно должно быть в выводе.
- **Тесты гоняются с корня репозитория:** `npm test`, не workspace-scoped. Базовая линия на момент написания плана — **925/925 зелёных**.
- **Гейты перед мержем:** `npm run typecheck` → 0, `npm run lint` → 0, `npm test` → все зелёные.
- **Коммиты маленькие и атомарные**, по одному на задачу, только после зелёных тестов. Сообщения по-английски, тело — при необходимости по-русски.
- **Мерж в `main` = выкладка на прод** ([ADR 023](../../adr/023-continuous-deploy-from-main.md)).
- **`--s1…--s8` идентичны в обеих палитрах** и не переключаются никогда.
- **Обе палитры светлые.** Отдельной печатной ветки не заводить.

```ts
/** @param showTruck — рисуется ли обвес. Без него переднее поле под кабину и нижнее под ходовую
 *  не нужны: они остаются пустыми поясами и только мельчат груз (владелец, 2026-08-03). Полоса
 *  линейки (`topGutter`) остаётся всегда — линейка не обвес, она снаружи `data-truck-chrome`. */
export function truckFrame(vehicle: Vehicle, view: 'top' | 'side', showTruck = true): TruckFrame {
  const { length, width, height } = vehicle;
  const spanY = view === 'top' ? width : height;
  const frontGutter = showTruck ? height * GUTTER.front : 0;
  const wheelGutter = showTruck && view === 'side' ? height * GUTTER.wheel : 0;
  const topGutter = length * RULER_FONT * 2.8;
  return {
    frontGutter,
    topGutter,
    wheelGutter,
    outerW: frontGutter + length,
    outerH: topGutter + spanY + wheelGutter,
  };
}
```

- [ ] **Step 1: Написать ADR 025**

Создать `docs/adr/025-two-brand-palettes.md` по образцу соседних ADR (контекст → решение → последствия). Обязательное содержание:

- **Контекст.** До сих пор действовало «Ребренд = правка одного файла `theme.css`», тема — только светлая (MVP). Владелец, увидев артефакт G7 на устаревшей тёплой палитре из `docs/lovable/design-system.md`, захотел не выбирать между ней и текущей холодной зелёной, а переключать.

- **Отвергнутая альтернатива.** Выбрать тёплую единственной и сделать честный ребрендинг. Отклонена владельцем.
- **Не решается этим ADR.** Тёмная тема. Путь к ней по-прежнему открыт токенами, но в объём не входит.

```ts
// Тема = фирменная палитра, не светлая/тёмная (ADR 025). Обе палитры светлые; `forest` —
// умолчание и живёт в голом `:root`, поэтому для неё атрибут СНИМАЕТСЯ, а не ставится в
// 'forest': так каскад имеет ровно один источник умолчания.
import { useCallback, useState } from 'react';

export type ThemeName = 'forest' | 'warm';

export const THEME_STORAGE_KEY = 'ladungsplaner.theme';

const isTheme = (v: unknown): v is ThemeName => v === 'forest' || v === 'warm';

/** Тема из хранилища. Любое неизвестное значение и любой отказ хранилища (Safari private mode
 *  бросает на доступе) — `forest`: тема не то, ради чего стоит падать. */
export function readTheme(): ThemeName {
  try {
    const raw = localStorage.getItem(THEME_STORAGE_KEY);
    return isTheme(raw) ? raw : 'forest';
  } catch {
    return 'forest';
  }
}

export function applyTheme(name: ThemeName): void {
  const root = document.documentElement;
  if (name === 'forest') root.removeAttribute('data-theme');
  else root.setAttribute('data-theme', name);
  try {
    localStorage.setItem(THEME_STORAGE_KEY, name);
  } catch {
    // Не смогли запомнить — тема всё равно применена на эту сессию.
  }
}

export function useTheme(): [ThemeName, (next: ThemeName) => void] {
  const [theme, setThemeState] = useState<ThemeName>(() => {
    const t = readTheme();
    applyTheme(t);
    return t;
  });
  const setTheme = useCallback((next: ThemeName) => {
    applyTheme(next);
    setThemeState(next);
  }, []);
  return [theme, setTheme];
}
```

  Уже используется для броска из кузова во двор. **При выключенной группировке `layout.bays` пуст**, и функция возвращает чистый индекс потока — ровно индекс в `orderedTiles`, никакого перевода координат не нужно. Третий аргумент в нашем случае не передаётся.
  Также: `warehouseFloor(load, tiles, opts)` с `showTruck` из задачи 2.
- Produces: ничего наружу; поведение целиком внутри `LadeplanScreen`.

**Известное ограничение, которое надо принять осознанно.** Порядок двора хранится как список
**`cargoTypeId`** (`setBufferOrder(snapshot)`, где `snapshot = orderedTiles.map(t => t.cargoTypeId)`),
а `orderedTiles` разбирает его FIFO-очередью на тип. Значит перестановка различает **типы груза**,
но не две плитки одного типа: попытка передвинуть остаток `EPAL 3 ×12` мимо полной стопки
`EPAL 3 ×17` окажется no-op, потому что в списке они обе просто `p3`. Это свойство уже существующей
модели, а не новой правки — тем же ограничением обладает бросок из кузова. Задача его **не чинит**:
чинить значит переводить порядок двора с типов на идентичности плиток, а это отдельная работа.
Шаг 1 пинит ограничение тестом, чтобы оно было явным, а не сюрпризом; в beads на него заводится
отдельная задача.

```tsx
/** Переставить стопку двора с позиции `from` на позицию `to` в порядке потока. `to` приходит от
 *  `insertionIndexAt` как индекс ВСТАВКИ, то есть считается до изъятия элемента — поэтому при
 *  движении вправо целевой индекс уменьшается на единицу. Перестановка на то же место — no-op:
 *  жест, ничего не изменивший, ничего и не фиксирует (тот же довод, что у переноса загона).
 *
 *  Порядок хранится списком `cargoTypeId`, а не идентичностей плиток, поэтому две плитки ОДНОГО
 *  типа между собой не переставляются — см. «Известное ограничение» в шапке задачи. */
const reorderYard = (from: number, to: number) => {
  const target = to > from ? to - 1 : to;
  if (target === from) return;
  const next = orderedTiles.map((t) => t.cargoTypeId);
  const [moved] = next.splice(from, 1);
  next.splice(target, 0, moved);
  setBufferOrder(next);
};
```
