## Что сделано

Нажатие «Рассчитать» с невалидным вводом молча давало пустой лист. Причина была шире, чем «не
рендерим `layout.errors`»:

| Слой | Было | Стало |
|---|---|---|
| Сборка груза | два независимых места (`handleCalculate` и Demo) | один `toCargoList`, его же зовёт валидация |
| Сообщения | только локальные проверки `setupMessages` | `allMessages` = локальные + коды `validateLoad`, живьём на каждый рендер |
| Кнопка | считала и выдавала пустоту | отказывает: есть адрес — переход к строке, нет — фокус в панель причин |
| `App` | принимал раскладку с `errors` как успех | не пускает её в состояние ни при расчёте, ни при восстановлении из localStorage |
| Объявление | `setup.calcDone` безусловно, врало при отказе | только по признаку принятия, числами ПРИНЯТОГО груза |

Строки с количеством 0 больше не входят в заявку: обнуление — законный способ временно исключить
позицию, но движок проверял её габариты независимо от количества, и обнулённый крупный груз молча
рвал расчёт. Видимое следствие: такая строка исчезает из легенды, разбора по заказам, PNG, печати и
JSON-экспорта.

## Решения

- **Подавление намеренно несимметрично.** Локальная ошибка по строке глушит коды движка по ней же
  (одно «укажите размеры» вместо трёх `ERR_INVALID_DIMENSION`); обратно — ровно одна пара:
  `ERR_CARGO_EXCEEDS_VEHICLE` прячет `tooTall`. Широкое обратное правило отвергнуто по находке
  codex: оно проглатывало предупреждение о дубле Auftrags-ID, которое относится к ЗАКАЗУ, а
  адресовано первой его строке. И `tooTall` не дубликат: локальная проверка смотрит исходную высоту,
  движок — все разрешённые ориентации (ADR 013).
- **Предохранитель живёт в `App`, а не только в экране.** Гейт экрана — удобство и адресация; Demo и
  восстановление сохранённого плана идут мимо него, поэтому инвариант стоит на границе системы.
- **Новых ключей локалей не заводили:** состояние «расчёт невозможен» уже объявляет существующая
  живая область шапки `setup.header.calcBlocked`, чей счётчик теперь включает и коды движка.
- **Бамп контракта `0.16.0` → `0.17.0`** — по прецеденту репозитория: экспонирование символа
  (`VALIDATION_ERROR_CODES`, тип `ValidationErrorCode`) аддитивно меняет контракт, даже когда
  поведение не менялось.
- **Граница честности адресации:** `loadSetup` не проверяет уникальность `p.id`, поэтому испорченный
  черновик с дублями подсветит одну строку из двух. Не чинится здесь — это `p3p.15`.

## Грабли

1. **Пять тестов из плана были зелёными ПО ПОСТРОЕНИЮ.** Прогон тестов такого не ловит — они
   проходят. Классы: фикстура не доводит до проверяемой ветки движка (`state: 'verschachtelt'` без
   шага → `nestable: false`, ветка `ERR_INVALID_NESTING` не выполняется); клик перехватывается
   незамоканным `window.confirm` (в jsdom это `notImplementedMethod`: печатает `Error: Not
   implemented` в stderr и возвращает `undefined`, то есть «отменить»); фикстура даёт адресуемую
   ошибку там, где проверяется безадресный путь; значение вместо фокуса (`toHaveValue` истинно и без
   навигации); несуществующее значение перечисления (`rotation: 'all6'`).
   **Лекарство, которое сработало:** мутационное доказательство — убрать проверяемую строку
   производственного кода, увидеть FAIL, вернуть, увидеть PASS. Требовать его в каждом фикс-раунде.
2. **Задача может обесценить тест ПРЕДЫДУЩЕЙ задачи, и per-task ревью этого не увидит.** Тест
   предохранителя `App` (задача 3) перестал доходить до предохранителя, когда задача 4 добавила
   свой гейт в экране: инвариант удалялся с 144 зелёными тестами. Поймало только финальное ревью
   всей ветки — **стыки между задачами не покрыты ничем, кроме него**. Изоляция потребовала подмены
   `calculateLayout` при живом `validateLoad` (отдельный файл `App.guard.test.tsx`, потому что
   `vi.mock` действует на весь файл).
3. **Кросс-модельная проверка окупается на ДИЗАЙНЕ, а не на коде.** Оба прохода `codex exec` нашли
   то, чего не видел ни один тест: обход гейта через Demo и localStorage; безусловное объявление
   `setup.calcDone`, врущее уже при геометрическом отказе; недостижимость `ERR_EMPTY_LOAD` оказалась
   ложной (заказ с `positions: []` проходит `loadSetup`); карта `cargoTypeId → where` не выполняет
   обещанного при дублях id.
4. **Утверждение «недостижимо с этого экрана» требует проверки поля ввода, а не рассуждения.**
   Спека объявила `ERR_INVALID_QUANTITY` недостижимым; на деле `Measure` — `type="number"` без
   `min`, поэтому `-5` доходит до движка и даёт адресуемую ошибку.
5. **Продакшн-код ревью приняло во всех пяти задачах без единой правки.** Все находки — в тестах и
   документации. Цена плана, написанного без проверки механик, платится не багами, а ложно-зелёными
   гейтами.
